# LX-Sync v0.2.0

`0.2.0` 是向后兼容的管理能力更新。它不改变 LX Music v4 wire format、握手文本或 `featureVersion`，也不新增 PostgreSQL migration。

## 新功能

- 管理端支持创建、改名和删除自建歌单。
- 支持按歌曲 ID 批量移动、复制和移除歌曲，完整保留字符串与数字 ID 的类型。
- 支持把历史 `list` / `dislike` 快照导出为 `lx-sync.snapshot` v1 JSON 文件。
- 管理端写入成功后向同一用户已就绪的在线 LX 客户端广播，客户端确认后才推进设备 baseline。
- 管理 UI 重新设计，补齐歌单搜索、歌曲搜索、分页、批量选择、409 冲突恢复和移动端导航。
- 正文排版统一为 Web `14px/20px`、Android 风格窄屏 `16px/24px`、iOS WebKit 窄屏 `17px/22px`。

## 兼容性

- 数据库仍为 PostgreSQL 18，schema 与 `0.1.3` 相同，不需要迁移。
- LX v4 `list` / `dislike` feature version 均保持 `1`，`message2call@0.1.3` 保持不变。
- 管理 API 只新增同源、Cookie 鉴权的歌单和快照导出端点；原有端点保持兼容。
- 部署模型仍为单实例模块化单体，不支持多副本 WebSocket 广播。

## 安全与一致性

- 歌单写入继续使用用户级串行任务与 PostgreSQL head 行锁/CAS。
- 快照、head、裁剪和受控审计记录在同一事务中提交或回滚。
- 审计和广播失败日志不包含歌名、歌曲 payload、访问码、设备原始标识或歌单原始 ID。
- 快照导出要求有效管理会话，响应禁止缓存；导出文件包含同步数据，不应公开分享。

## 升级与回滚

升级前同时备份 PostgreSQL 与当前 `MASTER_KEY`。正式镜像发布后应使用 GitHub Actions 记录的不可变 `sha256` digest 部署，不使用 `latest`、`edge` 或仅版本标签。

本版本不自动部署生产环境。需要回滚时，可切换到已验证的 `v0.1.3` 镜像：

```text
ghcr.io/elykia093/lx-sync@sha256:e9860e8350ef60d3ab298a9dc54663030b263c7ca425926eb0782b668113b8f2
```

由于没有 schema migration，应用回滚不需要数据库降级。仍应保留升级前备份；若 `v0.2.0` tag 后发现必须修改代码的问题，应发布 `0.2.1`，不得移动或覆盖 `v0.2.0` tag。
