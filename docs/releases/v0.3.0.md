# LX-Sync v0.3.0

`0.3.0` 是向后兼容的管理端导航更新。它不改变 LX Music v4 wire format、握手文本、`featureVersion`、管理 API 或 PostgreSQL schema。

## 新功能

- 管理端侧栏按“概览”“同步管理”“当前用户”和“系统”分组，减少空白并提升高频入口的可达性。
- 仪表盘增加“服务概况”“同步用户”“新增用户”快捷入口。
- 用户详情页按当前用户显示“用户设置”“设备管理”“歌单管理”“快照历史”上下文入口。
- 二级入口复用现有页面与 hash 锚点，提供当前区域活动态和对应顶部标题，不新增空页面或后端接口。
- 移动端继续使用原有导航抽屉、焦点约束和关闭行为；点击二级入口后关闭抽屉并定位目标区域。

## 兼容性

- LX v4 `list` / `dislike` feature version 均保持 `1`，`message2call@0.1.3` 保持不变。
- 数据库 schema 与 `0.2.0` 完全相同，不需要 migration 或数据写入。
- 管理 API、会话、Origin 校验、Cookie、查询缓存和管理写路径均未改变。
- 部署模型仍为单实例模块化单体，不支持多副本 WebSocket 广播。

## 验证

- 本地门禁覆盖 Biome、TypeScript、Vitest 和生产构建。
- Playwright Chromium 覆盖桌面分组、活动态、hash 定位、移动端抽屉关闭、响应式布局和横向溢出，并保存桌面与移动端截图。
- 真实 PostgreSQL integration、完整管理端 E2E、双架构镜像、SBOM 和 provenance 由 PR、`main` 与 tag workflow 继续执行。
- 本版本未执行真实 iPhone/iOS WebView 测试；维护者已取消该发布闸门，Chromium 响应式证据不能等同于 iOS 真机证据。

## 升级与回滚

升级不需要数据库迁移或配置变更。生产部署必须使用 tag workflow 记录的不可变 OCI digest，不使用 `latest`、`edge` 或仅版本标签。

部署前保留当前 compose、PostgreSQL 备份、`MASTER_KEY` 托管记录和 `v0.2.0` 实际镜像 digest。若健康检查、管理登录、静态资源或导航关键路径失败，恢复部署前 compose 并按记录的 `v0.2.0` digest 重建单实例容器。

本版本不配置 HTTPS。继续使用公网 HTTP 会暴露管理密码、访问码、Cookie 和 WebSocket 凭据；该部署不能视为安全生产配置。
