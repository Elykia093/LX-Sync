# LX-Sync v0.4.0

`0.4.0` 是向后兼容的迁移能力更新。它新增官方 LX Music 同步服务器 data format v2 的离线导入入口，强化 `XCQ0607/lxserver v2.0.0` 导入校验，并按部署需求取消管理员密码 12 位最低长度限制。LX Music v4 wire format、握手文本、`featureVersion`、管理 API 和 PostgreSQL schema 均保持不变。

## 新功能与修复

- 新增 `lyswhut/lx-music-sync-server 2.1.2` data format v2 导入工具，读取完整 `DATA_PATH` 备份和单独的受校验 JSON 用户配置。
- 迁移官方服务器与 `lxserver v2.0.0` 的 server ID、用户认证派生密钥、设备、设备密钥、`list` / `dislike` 当前 head、物理快照和设备 baseline。
- 官方导入遇到未被 JSON 配置映射的用户目录时直接拒绝，避免静默漏迁用户数据；`lxserver v2.0.0` 继续在 dry-run 摘要中报告 orphan 目录。
- 两个导入入口均默认只执行脱敏 dry-run；apply 要求独立环境开关、目标数据库名确认、空专用 schema，并在单个事务中写入业务数据与审计后复核行数。
- 导入器原样保留来源快照上限；全部合法历史快照会先写入，后续产生新快照时再按上限裁剪未被 head 或设备 baseline 引用的历史。
- `ADMIN_PASSWORD` 校验范围从 12–256 调整为 1–256。生产部署仍应使用密码管理器生成的长随机密码。
- 协议集成测试客户端忽略移动端文本心跳 `ping`，避免把兼容心跳误当 JSON RPC frame。

## 兼容性与数据影响

- LX v4 `list` / `dislike` feature version 均保持 `1`，`message2call@0.1.3` 保持不变。
- PostgreSQL schema 与 `0.3.0` 相同，不新增 migration。
- 管理 API、Cookie 会话、Origin 校验、前端响应 schema 和同步冲突语义均未改变。
- 导入只支持空的 LX-Sync 专用数据库或专用 schema，不支持向已有 LX-Sync 数据增量合并或覆盖重导。
- 官方 JSON 配置只用于恢复不会写入 `DATA_PATH` 的用户名、连接访问码和用户级选项；工具不会加载或执行旧 `config.js`。

- 本地门禁覆盖 Biome、TypeScript、Vitest、生产构建和两个构建后导入 CLI 入口。
- 单元测试覆盖官方 JSON 拒绝执行、遗漏用户目录、空 baseline、快照上限、超限歌单和管理员密码长度边界。
- 真实 PostgreSQL integration 覆盖两个来源的原子导入、错误主密钥整体回滚、双域 head、设备 baseline、凭据解密和脱敏审计事件。

## 迁移与发布

正式替换旧服务器时必须先停写，再制作新的完整备份，并导入全新空目标；staging 数据库或曾执行测试写入的目标不能复用。官方来源按 [官方同步服务器迁移手册](../migrate-from-lx-music-sync-server.md) 操作，`lxserver v2.0.0` 来源按 [lxserver v2.0 迁移手册](../migrate-from-lxserver-v2.md) 操作。

生产部署必须使用 tag workflow 记录的不可变 OCI digest，不使用 `latest`、`edge` 或仅版本标签。发布后至少验证 `/health/live`、`/health/ready`、管理登录、LX `/hello`、已有设备认证、新设备注册、`list` / `dislike` 首次同步与增量传播，并检查日志和审计不含凭据或同步内容。

## 回滚与已知风险

切换前保留旧服务 compose、停止时刻的完整源数据备份、数据库备份、密钥托管记录和旧容器恢复命令。新服务发生健康、认证、同步或数据核对失败时，在旧数据尚未恢复写入前停止新服务并恢复旧服务监听。

一旦客户端已在新服务写入，旧服务数据会与新库分叉；直接回滚到旧服务会丢失切换后的新变更。此时应暂停写入、导出并评估差异，不能把容器回滚当作数据回滚。

本版本不自动配置 HTTPS。公网 HTTP 会暴露管理密码、访问码、Cookie 和 WebSocket 凭据，只能视为临时测试入口；安全生产部署必须使用可信 TLS 终止和 WSS。
