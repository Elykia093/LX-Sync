# LX-Sync v0.5.0

`0.5.0` 是向后兼容的歌单管理能力更新。它为自建歌单增加独立的首选音质设置，补齐管理 API、React 管理端、PostgreSQL 持久化和删除一致性，并更新经过锁定的运行时依赖。LX Music v4 wire format、握手文本、`featureVersion` 和 `message2call@0.1.3` 均保持不变。

## 新功能与修复

- 自建歌单支持 `128k`、`320k`、`flac`、`hires`、`atmos`、`atmos_plus` 和 `master` 七档首选音质，也可清除为跟随客户端设置。
- `PATCH /api/v1/users/:userId/playlists/:playlistId` 新增可选 `quality` 字段；字段缺失保持原值，`null` 清除当前设置，未知值和未知请求字段继续被 strict schema 拒绝。
- 歌单摘要和详情新增可空 `quality` 响应字段；管理端可查看、修改和清除该设置，旧服务缺失该字段时前端按 `null` 兼容。
- 音质偏好与 LX 同步快照分离，更新时不会覆盖歌单的 `source`、`sourceListId` 或其他 wire metadata，也不会提升 LX feature version。
- 管理端删除、LX 客户端同步删除以及恢复到不包含某歌单的历史快照时，服务端会在同一数据库事务内清理孤立偏好。
- 更新 Fastify、Kysely、PostgreSQL 驱动、React、Vite、Playwright、Biome 等精确锁定依赖；协议基线依赖保持不变。

## 兼容性与数据影响

- 新增 migration `002_playlist_preferences`，创建 `playlist_preferences` 表：`user_id` 外键指向 `sync_users` 并级联删除，`user_id + playlist_id` 为复合主键，`quality` 由数据库 CHECK 约束为七档合法值。
- 迁移只新增空表，不扫描、重写或回填 `sync_snapshots`。升级前已有歌单的首选音质默认为 `null`。
- 首选音质是歌单的当前管理偏好，不属于历史快照。读取旧快照时叠加当前偏好；同一快照内容上的并发偏好更新按最后一次事务提交结果生效。
- LX 客户端仍只同步 `list` 和 `dislike` 原有数据。旧客户端、根同步路径、可选 scoped 路径和已有设备密钥继续兼容。
- 管理 API 仅增加可选请求字段和新增响应字段，现有不发送 `quality` 的消费者保持原行为。

## 验证范围

- `pnpm check` 覆盖 Biome、TypeScript、Vitest 和生产构建。
- 真实 PostgreSQL 18 integration 覆盖 migration、新表约束、偏好写入/替换、快照外存储、LX 删除清理、快照恢复清理、CAS 和事务回滚。
- Playwright 覆盖管理端音质选择、清除、冲突恢复和桌面/窄屏布局；发布 workflow 继续验证 amd64/arm64 镜像、SBOM、GitHub provenance 和 tag 提升后的不可变 digest。

## 升级与发布

升级前备份 PostgreSQL 和当前 `MASTER_KEY`，并保留 `v0.4.0` 的不可变镜像 digest。新镜像启动时自动执行向前 migration；迁移完成后验证 `/health/live`、`/health/ready`、管理登录、歌单读取和音质写入、LX `/hello`、已有设备同步及日志脱敏。

生产部署必须使用 tag workflow 记录的 `ghcr.io/elykia093/lx-sync@sha256:<digest>`，不使用 `latest`、`edge` 或仅版本标签。本版本发布 tag 只负责生成制品，不自动切换生产服务器。

## 回滚与已知风险

`v0.4.0` 不读取 `playlist_preferences`，但可在新增表保留时继续运行，因此代码回滚不需要执行 down migration。回滚期间已保存的音质偏好不会生效；再次升级到 `0.5.0` 后会恢复读取。若人工执行 down migration，表内偏好会被删除且无法由 LX 快照恢复。

本功能只保存歌单管理偏好，不改变 LX 播放器的 wire 数据，也不提供 WebDAV、Web 播放器、Subsonic、本地音乐或设置/音效同步。生产切换仍需单独批准，并在切换后验证真实反向代理、TLS/WSS、管理 Origin 和关键同步路径。
