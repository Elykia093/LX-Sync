# LX-Sync v0.6.0

`0.6.0` 增加同步连接的队列容量保护，修复断线、并发连接和管理端状态竞态。沿用现有依赖、数据库 schema、管理 API 与 LX Music v4 wire format；握手文本、`featureVersion`、`message2call@0.1.3` 和根/scoped/mobile 同步入口保持兼容。

## 同步服务修复

- 在异步初始化前绑定 WebSocket 错误和关闭处理，超大帧、非法帧或网络错误不再成为未监听的进程错误。
- 自然断线、主动关闭和发送失败立即停用连接、清除就绪状态并退出在线 registry；未开始的排队任务被丢弃，已有用户级串行任务和数据库事务边界保持不变。
- 异步用户查询或旧设备任务等待期间断线，不再登记幽灵连接；同设备并发握手时，登记步骤同步复核并替换旧连接，防止双活和漏广播。
- 入站解析队列限制为 32 条 / 16 MiB，已解析但未完成的 RPC 另受 32 条 / 16 MiB 预算限制，避免消息解析结束后业务请求继续无限积压。未完成的重复请求 ID 被拒绝；RPC 响应继续处理，保持双向同步可用。
- 出站队列限制为 256 条 / 16 MiB；补齐压缩前后单条消息 8 MiB 和 socket 缓冲预算，写入回调完成后释放容量，发送失败关闭连接。
- 断连后销毁未完成的 RPC；异步响应不再通过抛异常制造未处理的 Promise 拒绝。

## 管理端与测试修复

- 切换同名、同音质歌单时清除上一歌单的名称和音质草稿；歌曲详情仍在加载时也不能将旧草稿提交到新歌单。
- 退出登录或受保护请求返回 401 时，取消并等待在途查询结算，再清除受保护缓存并写入未登录状态，防止迟到的会话轮询响应恢复旧登录态。
- 真实浏览器 E2E 必须显式设置 `ALLOW_TEST_DATABASE_WRITE=1` 并使用名称包含独立 `test` 段的 PostgreSQL 数据库，拒绝复用已有服务和真实模式的 `E2E_SKIP_WEBSERVER=1`。mock 模式只发现 `*.mock.spec.ts`，无需数据库。

## 验证范围

- Vitest 回归覆盖连接错误、断线清理、初始化中断线、同设备并发、出站消息上限、未完成 RPC 预算、队列容量回收及会话竞态。
- Playwright 回归覆盖同名歌单切换、保存失败恢复、退出和 401 后的迟到会话响应；真实 PostgreSQL 管理员旅程由 CI 执行。
- 发布门禁包括 `pnpm check`、覆盖率、真实 PostgreSQL 协议/事务集成、Playwright，以及 amd64/arm64 镜像、SBOM、provenance 和最终标签 digest 核验。

## 升级、回滚与边界

本次不新增数据库迁移、环境变量或依赖升级。正常同步无需客户端调整；超过队列预算或单帧上限的连接会关闭，应减少单次数据量或并行请求后重连。这些上限是资源保护边界，不代表并发容量压测结论。

升级前保存 PostgreSQL 和独立保管的 `MASTER_KEY` 备份。本版本提供 GitHub Release 与 tag workflow 生成的镜像，不自动切换生产服务器；部署使用发布 workflow 核验的不可变 `ghcr.io/elykia093/lx-sync@sha256:<digest>`，并验证健康检查、管理登录、已有设备重连和双域同步。

可直接回滚到已验证的 `0.5.0` 镜像，无需 down migration：

```text
ghcr.io/elykia093/lx-sync@sha256:04730bdd8d06b0acb30cbf2f4134fe6b000ba8eee032c63a8e3239b1f49e285a
```

回滚会重新暴露本次修复的连接及管理端竞态。应用继续限定为单实例；本次不改变设备基线、快照 CAS、事务、鉴权或 LX 加密设计。
