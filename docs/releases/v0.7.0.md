# LX-Sync v0.7.0

`0.7.0` 增加歌单管理能力、并行同步初始化和可选的本地监控栈。LX Music v4 握手、wire format、`featureVersion`、`message2call@0.1.3`、根/scoped/mobile 同步入口及数据库 schema 保持不变。

## 新增与改进

- 管理端歌单支持首页、末页和页码跳转；按当前快照和筛选结果确定页数。
- 新增指定快照下的单歌单完整 JSON 导出，格式为 `lx-sync.playlist` v1，不受分页或搜索影响。
- 新增复制预检查，报告目标歌单中的重复歌曲；正式复制后分别返回新增和跳过数量。预检查只读，不替代最终写入的快照 CAS。
- `list` 和 `dislike` 域在一次连接初始化中并行启动，用户级串行任务、数据库 head 行锁和 CAS 保持不变。没有基准测试结果，不承诺固定比例的延迟提升。
- 增加 Prometheus 指标、仪表盘和告警。监控服务从默认 Compose 移至 `compose.monitoring.yml`，端口绑定本机回环地址，Grafana 凭据需显式配置。
- `/metrics` 不要求鉴权；生产部署须限制到受信监控网络，同时阻止公共反代和应用宿主端口的未授权直连。

## 移除

- 移除 `XCQ0607/lxserver` v2 本地数据导入兼容入口和对应迁移手册。官方 `lx-music-sync-server` data format v2 导入工具继续保留。

已部署 LX-Sync 的数据库数据不受影响。本版本不提供 lxserver v2 数据目录的内置迁移入口。

## 升级与回滚

- 不需要数据库迁移或客户端设置变更。
- 若原先通过默认 Compose 启动 Prometheus/Grafana，需在 `.env` 设置独立的 `GRAFANA_ADMIN_USER` 与 `GRAFANA_ADMIN_PASSWORD`，并使用 `docker compose -f compose.yaml -f compose.monitoring.yml up -d` 启动监控。
- 回滚可使用此前发布记录中的 `0.6.0` 不可变镜像 digest；没有数据库迁移，无需 down migration。不要使用可变镜像标签作为生产回滚目标。
